# M4 Parallel Build: builder contract

Seven builders work in parallel, each in its own git worktree branched from `main` at the commit that
adds this file. The integrator (lead) merges in this order, running the full suite after each merge:
**checks → filters → instr → state-scope → verify → console → skills**.

Spec: [DESIGN.md](../../../DESIGN.md), [CONTRACTS.md](../../../CONTRACTS.md) v1.2,
[RESEARCH.md](../../../RESEARCH.md). This file adds the cross-builder interfaces M4 needs. Where this file
and CONTRACTS.md differ, this file wins for M4; the integrator folds it into CONTRACTS.md at merge.

---

## 1. Shared rules (every builder)

1. **TDD.** Write the failing test, run it and see it fail for the expected reason, implement, run it
   green, run the whole suite (`uv run pytest -q -p no:cacheprovider`). A test that passes before the
   implementation exists is a finding about the test.
2. **Environment.** Windows 11, Python 3.12, uv. No Docker, no WSL, no make on this machine. Use `uv run …`.
   Tests that need a container runtime get `@pytest.mark.docker`; tests that call OpenAI or LangSmith get
   `@pytest.mark.live`; tests that need a Playwright browser get `@pytest.mark.browser` and skip cleanly when
   Chromium is not installed (`uv run playwright install chromium` installs it). Default `uv run pytest`
   must pass with no network, keys, Docker, or browser.
3. **Write scope.** Change only the paths in your section. Never edit: `src/shipharness/cli.py`,
   `pyproject.toml`, `uv.lock`, `Makefile`, `.github/`, `CONTRACTS.md`, `DESIGN.md`, `RESEARCH.md`,
   `README.md`, `CHANGELOG.md`, `VERIFICATION.md`. If you need one of those changed (a dependency, a pytest
   marker, a contract field, a doc correction), say so in your report with the exact change.
4. **CLI.** Put commands in `src/shipharness/<your package>/commands.py` exposing
   `def register(app: typer.Typer) -> None`. The integrator wires them into `cli.py`. Every command prints a
   cost summary line at exit (`Cost: $X (…)`), as `shipharness doctor` does.
5. **Untrusted workspace.** Everything inside an arm workspace (files, `.git`, links, bytes, model-chosen ids)
   is hostile. Host code never runs `git` against the agent's `.git/config` (use `shipharness.runner.git`
   helpers, which use an isolated git dir), never follows links out of the workspace (use
   `shipharness.runner.tools.iter_workspace_files`), never executes agent-written code on the host except via
   `LocalSandbox` (labelled UNSANDBOXED). Agent-written code runs only in a container (gate: arm container;
   referee: referee container).
6. **Secrets.** Keys are `SecretStr`; never print, log, trace, export, or pass them into a container. Use
   `shipharness.logging.redact` / `mask_keys` on anything derived from agent output that you persist.
7. **Writing rules** (any Markdown you write, including skills and TeamTrack docs): source wording from
   RESEARCH.md (for example "map" / "table of contents" for AGENTS.md, "grading criteria" not "rubric",
   "existing tests keep passing" not PASS_TO_PASS); no banned words (`uv run python scripts/lint_prose.py
   <files>` must pass); no emoji; every number has a source or a VERIFICATION entry. **Clean room:** write
   from the primary sources only; never open, copy, or adapt third-party course repositories or skill packs.
8. **Walkthrough anchors** (`# [walkthrough:S<N>:<name>] start` / `end`, at most 40 lines, unique ids):
   add the ones listed in your section; `uv run python scripts/anchors.py check` must pass.
9. **Commits.** The repo config commits as `ANI-IN <44803072+ANI-IN@users.noreply.github.com>`; do not change
   it. Small conventional commits (`feat(checks): …`). No `Co-authored-by` or tool-attribution lines.
   Before reporting, run `git log --format='%an <%ae> | %cn <%ce>' main..HEAD | sort -u` (exactly one
   identity) and leave the worktree clean.
10. **Lint.** `uv run ruff check .` and `uv run ruff format --check .` pass.
11. **Cost.** No builder needs OpenAI except B-verify's reviewer live test (cap $0.01). Do not run agents.

## 2. Cross-builder interfaces (new in M4)

**I-1 Check runner (owner B-checks).** One entry point used by the verify gate (inside the arm container)
and the referee (inside the referee container):

```
python -m shipharness.checks.runner --build <dir> --checks r1_tenant,r2_roles,... \
    --checkpoint <tag> --feature <id> --seed <int> [--params <json-file>] [--baseline <json-file>]
```

- stdout: one JSON document `{"results": [CheckResult, ...]}`; stderr: one JSON line per progress update
  `{"check": "R1", "done": 37, "total": 112, "label": "R1 probes 37/112"}`.
- `--params` carries per-check inputs (hidden test node ids, shipped test files, allowed paths per phase,
  run-log path, exemptions). `CheckContext` gains `params: dict[str, Any]` (B-checks adds the field).
- `--baseline` is a previous runner output for the checkpoint; results are passed through `mark_baseline`.
- Check names (registry): `r1_tenant`, `r2_roles`, `r3_conventions`, `r4_idempotency`, `r5_audit`,
  `r6_layering`, `r7_migrations`, `regression`, `hidden_tests`, `diff_scope`, `flakiness`, `continuity`,
  `board`.
- Containers get the package via the image: B-checks updates `sandbox/Dockerfile` to copy `src/` to
  `/opt/shipharness/src` and set `PYTHONPATH=/opt/shipharness/src`.

**I-2 Tenant app adapter (owner B-checks).** Checks are generic for FastAPI services; app specifics go
through `shipharness.checks.adapter.TenantAppAdapter` with `create_app(build_dir, db_path)`,
`headers(org: str, role: str) -> dict`, `orgs() -> (home, other)`, `ids(org) -> dict[str, int]` (values
for path parameters such as `issue_id`, `project_id`, `user_id`), and `audit_count(app, org) -> int`. The
TeamTrack adapter ships built in; `shipharness check --adapter module:attr` loads another.

**I-3 Filter pipeline (owner B-filters).** As CONTRACTS §14 (`Filter`, `run_pipeline`, `Mutant`,
`run_mutant`). Filter 3 uses **filter-set** mutants only. Coverage via coverage.py JSON. Commands:
`shipharness testgen`.

**I-4 Layer modules and registration.** `harness/instructions/layer.py: InstructionsLayer`,
`harness/state/layer.py: StateLayer`, `harness/scope/layer.py: ScopeLayer`,
`harness/verify/layer.py: VerifyLayer`, each decorated `@register_layer`. Constructors take only keyword
arguments with defaults and accept `**kwargs` (ignore unknown keys): `Harness.from_names(names, **kwargs)`
passes the same kwargs to every layer. The integrator adds `shipharness/harness/layers.py` importing all four.

**I-5 Shared `LayerContext.state` keys.** Exact names:

| Key | Set by | Value |
|---|---|---|
| `last_claim` | runner loop (B-verify) | `{"phase": str, "claim": "done"|"not_done"|"none", "summary": str}` at every `finish` |
| `verify.gate` | VerifyLayer | last `GateResult.model_dump()` |
| `scope.passes_set` | ScopeLayer | `True` once `passes` was set for the feature |
| `state.handoff_path` | StateLayer | workspace-relative path of `session-handoff.md` after a session stop |
| `instructions.files_read` | InstructionsLayer | list of harness doc and skill paths the agent read |

The loop (B-verify) reads `state.handoff_path` for the `session_stop` event's `handoff_path`.

**I-6 Workspace layout and artifact ownership.** An arm workspace is a fresh git repo made from a filtered
export of `teamtrack/` at the checkpoint (owner B-verify, `ab/workspace.py`), created **outside the course
checkout** (`<system temp>/shipharness-ws/<ab_id>/<arm>/ws`). The export excludes `harness/**`,
`tests/hidden/**`, `mutants/**`, `reference/**`, `*.db`, `__pycache__/`. Harness artifacts are created by
layers in `prepare_workspace` and never exist in the bare arm:

| Artifact | Owner layer | Source |
|---|---|---|
| `AGENTS.md`, `ARCHITECTURE.md`, `docs/SECURITY.md`, `docs/RELIABILITY.md`, `docs/QUALITY_SCORE.md`, `docs/PLANS.md`, `docs/design-docs/**`, `docs/product-specs/**`, `docs/references/*-llms.txt`, `.agents/skills/**` | instructions | copied from `teamtrack/harness/instructions/` (mirrors the workspace layout) |
| `init.sh`, `progress.md`, `session-handoff.md`, `docs/exec-plans/active|completed/<feature>.md` | state | templates in `src/shipharness/harness/state/assets/` |
| `feature_list.json`, `feature_list.schema.json` | scope | built from the task (feature id, ticket, steps) |

`docs/HANDBOOK.md` (unstructured, every rule) stays in both arms.

**I-7 Scope reverts without git.** The scope layer keeps its own byte snapshot of the workspace (via
`iter_workspace_files`) at phase start and after every accepted change, and restores bytes / deletes new
files to revert. It never calls git.

**I-8 Gate.** VerifyLayer runs the check runner in the arm container via `ctx.sandbox.exec(...)`
(checks: R1-R7, `regression`, `board`) plus the clean-state check, writes `verify.gate`, and returns
`gate_fail` (feedback: first three failures, grep-friendly) or `gate_pass`. It never runs `hidden_tests` or
referee-set mutants.

**I-9 Referee (owner B-verify).** Fresh export + arm diff applied in a referee directory; the check runner runs
in a referee container (`SANDBOX_IMAGE_REFEREE`, network none) with hidden tests mounted read-only; then
referee-set mutants against shipped tests (B-filters' `run_mutant`), flakiness re-runs, blinded reviewer,
`ScoreRecord`, `verdict`. `DockerSandbox`/`docker_run_args` gain an optional `extra_mounts:
list[tuple[host, container, "ro"|"rw"]]` (B-verify adds it).

**I-10 OpenAI client.** Production `OpenAI(...)` clients are built with `max_retries=0` so
`classify_openai_error` sees every error (B-verify; ruling from the M3 review).

## 3. Builders

### B-checks
- **Writes:** `src/shipharness/checks/**`, `sandbox/Dockerfile`, `tests/unit/checks/**`.
- **Builds:** R1-R7 generic checks (DESIGN §5; endpoints from OpenAPI via `discover_endpoints`; R1 Acme
  user with Globex ids → expect 404, leak = 2xx with Globex data; R2 viewer writes → 403; R3 Schemathesis
  in-process ASGI with a recorded seed + list/error envelope assertions; R4 duplicate POST probe on every
  create endpoint, honouring `exemptions`; R5 audit row delta; R6 import-linter contract; R7 `alembic heads`
  = 1 and fresh `upgrade head`), `regression`, `hidden_tests` (pytest node ids from params), `diff_scope`
  (files changed vs allowed paths per phase, test-phase source edits), `flakiness` (shipped tests ×10),
  `continuity` (S2 measures from the run log: heads ≠ 1, duplicate table migration, ≥ 30% of session-1
  added lines removed in session 2), `board` (Playwright: login, board loads, only own-org cards; browser
  marker). Check runner (I-1), adapter (I-2), `shipharness check` command (exit 0 none new, 3 new
  violations, 1 error; `--json`). Dockerfile change (I-1).
- **Anchors:** `S4:probe` around the R1 probe loop in `checks/r1_tenant.py`.
- **Minors owned:** baseline key gets a detail key (review M5).
- **Done when:** every check has tests including a TeamTrack-base run with zero new violations except
  the documented `/v1/issues` R1 baseline, and a seeded-violation fixture per rule that the check catches.

### B-filters
- **Writes:** `src/shipharness/filters/**`, `src/shipharness/testgen/**`, `teamtrack/mutants/**`,
  `tests/unit/filters/**`.
- **Builds:** the five filters (DESIGN §7: imports and runs; passes 5 consecutive runs; adds line coverage
  or kills a filter-set mutant no existing test kills; real assertions and no mocking of the unit under test
  (AST); no source file changed during the test phase), `run_pipeline` with `test_proposed` /
  `test_filter_result` events and a discard reason for every test, targeted mutant runner (`Mutant`
  records, one at a time, original text must match, killed/survived/timeout/error), coverage helpers,
  `shipharness testgen --repo --module [--layers none|verify] [--max-tests N]` (uses the runner with the
  test phase only; for repos without a prepared image it runs in the learner's environment through
  `LocalSandbox`, clearly labelled UNSANDBOXED; `--sandbox docker --image` is accepted). TeamTrack
  mutants: about 4 per module for 20 base modules in `app/services/` and `app/repositories/`, split into
  `filter` and `referee` sets, each validated to be killed by at least one existing visible test.
- **Anchors:** `S4:filters` in `filters/pipeline.py`.
- **Done when:** each filter has pass and discard tests; the mutant files load and each mutant is killed by
  the visible suite (validation test); `testgen` runs end to end with a scripted model client.

## 5. Report format (every builder)

Branch name and final commit SHA; files added/changed (grouped); commands run with results (tests, lint, prose
lint, anchors); anchors added; deviations from this contract with reasons; requested changes to files outside
your scope (exact text); cost and traces used; open issues. Keep it under 600 words.
