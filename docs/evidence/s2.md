## How to use this page

This is the Section 2 part of the evidence page. It holds every run id, A/B id, finding id, commit
hash, and capture detail that the Section 2 pages rely on. The pages name a source or a result in a
few words and link to an anchor here. The score records and run logs behind the run ids are kept with
the course's private run records, not in this repository. Finding ids point to the course's research
notes, where each quote was checked against the source text.

The source anchors `src-openai-harness`, `src-anthropic-long-running`, and
`src-anthropic-harness-design` are defined once, in the Section 1 part. This part adds
`src-openai-exec-plans`.

<a id="s2-runner-fix"></a>

**A runner fix found by reading a run**

In run 3, `ab-20261016-213317-9a0ec1`, the harness arm called `finish(claim="not_done")` on its last
turn of session 1. Under the runner's rule at the time, any `finish` ended the build phase, so the
38-turn session never ran. The same early finish ended the build phase in the harness arm of
`ab-20261016-214959-de790f` (run 3), and in run 4 in all three bare arms
(`ab-20261016-232842-ac03b2`, `ab-20261016-234027-226a76`, `ab-20261016-235211-ea59a9`) and the
harness arm of `ab-20261016-234027-226a76`, after 9 to 12 turns. Fix (change 14, commit 501be88, both
arms): before the last build session, `finish(claim="not_done")` ends only that session
(`_next_session_runs`, `platform/src/shipharness/runner/loop.py`, lines 99-104; tests in
`platform/tests/unit/test_loop.py`). In the captured show-2 run, session 1 ended with
`claim_not_done` and session 2 ran.

<a id="s2-course-design"></a>

**Course design, not source claims**

- **Session turn budget.** The mechanism that produces the context reset (A3, F-a-65) at a fixed
  turn, the same for both arms. No source names it. `shipharness ab --session-budget 12,38`
  (commit 3e7c772); `make show-2` passes `SESSION_BUDGET` since commit fd9726c.
- **Initializer step as code.** A2's initializer is a model session with its own first prompt
  (F-a-49, F-a-52); the course writes the files with deterministic code, because one ticket fixes
  them.
- **Machine summary.** The harness-written part of the handoff; the agent's notes are kept as
  written (`handoff.merge`).
- **`progress.md`.** A2's `claude-progress.txt` (F-a-50), renamed.
- **House rules R1 to R7.** The course's name for A1's "golden principles" (F-a-99).
- **Primary measure for F2.** `continuity_failure`, registered before any run, threshold 30%
  (`REDONE_THRESHOLD_PCT`).
- **Assignment 2.** The step ledger, the rule that it is rebuilt from git at every stop, the test
  stand-in agent, and the four-session live task were designed for this course.
