# F4 Optimistic concurrency and issue history

Status: planned. Section S4.

## Goal

Two people editing the same issue never silently overwrite each other. The second save is refused
and the person reloads. Each issue also shows its change history.

## API

- `GET /issues/{issue_id}` returns the header `ETag: "<version>"`, the issue's version in double
  quotes, for example `ETag: "3"`.
- `PATCH /issues/{issue_id}`, `POST /issues/{issue_id}/assign`, and `POST /issues/{issue_id}/transition`
  require `If-Match: "<version>"`:
  - missing header: 428 `precondition_required`;
  - a value that is not the current ETag (an older version, or any other value): 412
    `precondition_failed`, and nothing changes;
  - the current ETag: the change is applied, `version` goes up by one, and the response carries the
    new `ETag`.
- Check order: 401 (no token), 403 (viewer), 404 (another org's or a deleted issue), then 428 or 412,
  then 422 (an invalid body, or a status change that is not allowed). For example a member who sends an
  invalid body without `If-Match` gets 428.
- The 412 and 428 responses are documented in the OpenAPI schema of the three endpoints.
- A refused write (403, 404, 412, 428, 422) adds no audit row.
- `GET /issues/{issue_id}/history` lists the issue's audit entries (entity `issue`, that issue's id)
  oldest first, as `AuditOut` items in the list envelope with `cursor` and `limit` (keyset by audit id).
  Any role may read it. Another org's or a deleted issue gives 404.

Existing tests that change an issue through these three endpoints must now send `If-Match`. Update
them by adding the header and nothing else.

## Board

The edit form on the issue page sends the version it was loaded with in a hidden field named
`version`. A save whose version is not the current one (or has no version) changes nothing and
returns HTTP 409 with an HTML page (an element with class `conflict`) that says the issue was changed
by someone else and links back to the issue. A save with the current version works as before.

## Out of scope

Weak ETags, `If-None-Match`, versions on other resources, merging edits.
