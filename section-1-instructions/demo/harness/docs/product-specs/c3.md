# C3 Filter a project's issues by priority

A small change to an existing list endpoint.

## Behaviour

`GET /projects/{project_id}/issues` accepts an optional `priority` query parameter: `low`, `medium`,
or `high`. With it, the list contains only the project's issues with that priority, using each
issue's current priority. Without it, the list is unchanged.

- Any other value gives 422 `validation_error`.
- The filter works with `cursor` and `limit` as every list does (house rule R3): keyset pagination by
  ascending id, and a cursor from a filtered page continues the filtered list.
- Deleted issues are never listed, as before. A project of another org, or an archived project, gives
  404 `not_found`, with or without the filter (R1). Any role may read the list.

## Where the change goes

`app/api/issues.py`, `app/services/issues.py`, `app/repositories/issues.py`, and tests in
`tests/visible/`.
